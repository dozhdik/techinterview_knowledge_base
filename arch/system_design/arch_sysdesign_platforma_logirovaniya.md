# Платформа логирования

## Задача

Нужно собирать и искать журналы множества сервисов при всплесках нагрузки.

## Главное

- Агенты отправляют структурированные записи.
- Буфер защищает от краткого отказа.
- Индексируют только необходимые поля и ограничивают срок хранения.

## Как устроено

Агенты собирают логи с узлов, добавляют метаданные сервиса и времени, затем отправляют их через буфер в централизованное хранилище с поиском. Политика хранения различается для оперативной отладки и аудита.

## Практический пример

После ошибки по trace ID инженер находит записи нескольких сервисов и восстанавливает последовательность вызовов без доступа на каждый сервер.

## Ограничения

Логи могут содержать секреты и персональные данные. Нужны фильтрация, ограничение доступа, защита от переполнения буфера и правило потери низкоприоритетных сообщений.

## Что оценить

Оцените объём логов по сервисам, длительность хранения, долю индексируемых полей и типичный срок поиска по инциденту. Отдельно спроектируйте путь при переполнении буфера: какие записи допустимо потерять, а какие нужны для аудита.

## На собеседовании

Посчитайте объём событий в день и объясните судьбу логов при недоступности хранилища.
