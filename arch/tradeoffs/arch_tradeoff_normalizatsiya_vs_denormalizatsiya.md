# Нормализация vs денормализация

## Суть выбора

Нормализация уменьшает дубли и аномалии записи; денормализация ускоряет конкретные чтения ценой синхронизации копий.

## Главное

- Реляционные связи удобны для изменяемых данных.
- Копии полезны для горячих запросов.
- Решение подтверждают профилем нагрузки.

## Как устроено

Нормализация хранит факт в одном месте и связывает сущности; денормализация копирует данные ради более дешёвого чтения. Копия создаёт обязанность поддерживать согласованность при изменении источника.

## Практический пример

Имя клиента хранится в таблице клиентов, но готовая карточка заказа может содержать его снимок для быстрого показа истории.

## Ограничения

Проверяйте семантику копии: исторический снимок и текущий профиль клиента — разные данные. Денормализация без политики обновления приводит к тихим расхождениям.

## На собеседовании

На заказах покажите, какие поля должны быть историческим снимком цены.
