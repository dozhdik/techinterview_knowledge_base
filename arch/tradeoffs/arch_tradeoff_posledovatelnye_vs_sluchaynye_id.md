# Последовательные vs случайные ID

## Суть выбора

Последовательные ID компактны и хорошо локализуют вставки; случайные ID помогают создавать значения независимо от общего счётчика.

## Главное

- Последовательность может раскрывать объём объектов.
- Случайный порядок ухудшает локальность некоторых индексов.
- Формат ID не заменяет права доступа.

## Как устроено

Последовательный ID компактно индексируется и легко генерируется централизованно, но может раскрывать порядок создания и создавать горячую область записи. Случайный ID распределяет ключи, но ухудшает локальность некоторых индексов.

## Практический пример

Для публичных коротких ссылок предсказуемый счётчик может позволить перебор соседних записей; случайный токен снижает эту предсказуемость.

## Ограничения

Случайность не заменяет авторизацию и проверку коллизий. Оцените размер пространства ключей, требования к сортировке по времени и особенности выбранной БД.

## На собеседовании

На URL shortener объясните конфликт между удобством генерации и предсказуемостью.
