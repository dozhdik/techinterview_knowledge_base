# Хеш-таблица

## Определение

Хеш-таблица — это структура данных, которая хранит пары `ключ → значение` и использует хеш-функцию для быстрого перехода к месту хранения элемента. В среднем она обеспечивает `O(1)` для поиска, вставки и удаления, но в худшем случае может деградировать до `O(n)`.

## Суть концепции

Идея хеш-таблицы в том, чтобы не искать элемент линейным проходом, а вычислить индекс или бакет по ключу через хеш-функцию. Ключ преобразуется в число, а затем это число используется для выбора позиции в таблице. Если распределение хорошее, нужный элемент находится очень быстро.

Но ключевая проблема хеш-таблицы — **коллизии**. Разные ключи могут давать один и тот же hash или попадать в один и тот же бакет. Поэтому хеш-таблица всегда должна иметь стратегию разрешения коллизий.

Две классические стратегии:
- **chaining** — в одном бакете хранится список или другая структура элементов;
- **open addressing** — при конфликте ищется следующая свободная ячейка по определённому правилу.

Производительность хеш-таблицы зависит от:
- качества хеш-функции;
- load factor;
- стратегии разрешения коллизий;
- частоты resize / rehash;
- реального распределения данных.

На собеседовании важно понимать, что `O(1)` у hash table — это не магия. Это средний случай при нормальной реализации. Если ключи распределяются плохо или таблица перегружена, производительность падает.

**Важно:** хеш-таблица **не поддерживает упорядоченность ключей** и **не даёт преимуществ для префиксных запросов, диапазонов и порядковых операций** — для этого обычно нужны деревья поиска, trie или другие упорядоченные структуры.

Хеш-таблицы чрезвычайно популярны, потому что хорошо подходят для:
- словарей и map;
- set;
- счётчиков частот;
- кэшей;
- группировки и индексирования данных.

## Ключевые характеристики

- **Что хранит**: пары `key -> value`
- **Основная идея**: вычислить индекс по hash-функции
- **Базовые операции**:
    - поиск
    - вставка
    - удаление
- **Средняя сложность**:
    - поиск `O(1)`
    - вставка `O(1)`
    - удаление `O(1)`
- **Worst case**:
    - поиск `O(n)`
    - вставка `O(n)`
    - удаление `O(n)`
- **Основная проблема**: коллизии
- **Стратегии разрешения коллизий**:
    - chaining
    - open addressing
- **Пространственная сложность**: `O(n)`

Hash table:

hash("god") -> 2

Оба ключа попали в один бакет -> коллизия
