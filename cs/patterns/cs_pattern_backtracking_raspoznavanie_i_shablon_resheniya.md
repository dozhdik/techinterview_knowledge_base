# Backtracking: распознавание и шаблон решения

## Суть паттерна

Backtracking — это паттерн перебора, при котором мы строим решение по шагам, проверяем частичную корректность и откатываем последний выбор, если он не ведёт к допустимому или полезному продолжению. Это не просто рекурсия, а рекурсия с систематическим выбором, проверкой ограничений и возвратом назад. Паттерн особенно полезен в задачах, где нужно перебрать комбинации, перестановки, размещения или все допустимые варианты при наборе ограничений.

Главная сила backtracking в том, что он позволяет не генерировать весь перебор слепо. Если на промежуточном шаге уже понятно, что текущее частичное решение не может привести к валидному ответу, ветвь можно обрезать сразу. Это называется pruning. Именно pruning делает backtracking практически полезным, иначе он превращается в тупой brute force.

На собеседовании этот паттерн обычно появляется в задачах на:
- permutations;
- combinations;
- subsets;
- N-Queens;
- Sudoku;
- word search;
- partitioning;
- генерацию строк или выражений по правилам.

Кандидат должен уметь не только написать рекурсивную функцию, но и чётко проговорить:
1. что является состоянием;
2. какие есть выборы на каждом шаге;
3. когда найдено полное решение;
4. когда нужно остановить ветвь раньше времени;
5. как делается откат состояния.

## Когда применять

Backtracking стоит рассматривать, если в задаче есть следующие признаки:

- нужно найти **все** решения, а не одно оптимальное;
- решение строится поэтапно;
- на каждом шаге есть несколько допустимых выборов;
- можно проверить частичное решение на валидность;
- можно откатить состояние после рекурсивного вызова;
- пространство решений экспоненциальное, но часть ветвей можно отсекать раньше.

### Типичные сигналы в условии

- “вернуть все комбинации / все перестановки / все разбиения”;
- “нужно расставить объекты по правилам”;
- “нужно найти любое валидное решение с ограничениями”;
- “из каждого состояния можно сделать несколько шагов”;
- “порядок выбора важен” или “каждый элемент можно взять / не взять”.

### Когда backtracking, скорее всего, не подходит

- задача сводится к линейному проходу или сортировке;
- решение можно выразить через локально лучший выбор — возможно greedy;
- нужно посчитать лучший результат по состояниям — возможно DP;
- нет смысла хранить путь, а нужен только факт достижимости — возможно BFS/DFS без backtracking.

def backtrack(state, path, result):
    if is_complete(state, path):
        result.append(path.copy())
        return

    for choice in get_choices(state, path):
        if not is_valid(choice, state, path):
            continue

        apply_choice(choice, state, path)
        backtrack(state, path, result)
        undo_choice(choice, state, path)
