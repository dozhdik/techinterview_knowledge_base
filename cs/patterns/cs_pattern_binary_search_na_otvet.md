# Binary Search на ответ (по пространству ответа)

## Суть паттерна

Иногда ответ — это число из большого диапазона, а проверить «подходит ли значение `x`» можно за разумное время функцией `can(x)`. Если множество допустимых ответов на прямой монотонно (все невалидные слева, все валидные справа, или наоборот), границу между «нет» и «да» можно искать **бинарным поиском не по массиву, а по пространству ответа**.

Типовой сюжет: минимизировать максимум нагрузки, вместимость, скорость, время и т.п., когда при увеличении кандидата проверка `can(x)` переходит из ложного в истинное (или наоборот).

## Когда применять

- есть **отсортированное по смыслу** пространство целочисленных или вещественных кандидатов;
- для кандидата `x` можно написать детерминированную проверку `can(x)`;
- выполняется **монотонность**: если `x` допустим, то все большие (или все меньшие) тоже допустимы — в зависимости от постановки;
- перебор всех `x` слишком дорог, а `can(x)` заметно дешевле, чем наивный полный перебор сценариев.

### Типичные сигналы в условии

- «найти минимальное значение, при котором возможно…»;
- «разбить на `k` частей так, чтобы максимум … был минимален»;
- «проверить, успеем ли за время `t`» + внешний поиск по `t`.

### Когда паттерн не подходит

- нет монотонности ответа относительно `can(x)`;
- проверка `can(x)` сама требует перебора без структуры;
- ответ не лежит на одной оси (не скаляр для бинпоиска).

def minimize_valid(left: int, right: int) -> int:
    while left < right:
        mid = left + (right - left) // 2
        if can(mid):
            right = mid
        else:
            left = mid + 1
    return left

### Мини-пример (идея)

Задача *Split Array Largest Sum*: минимизировать максимальную сумму среди `k` непрерывных кусков массива. Для фиксированного `mid` проверка `can(mid)` — жадно: сколько нужно кусков, если ни один не превышает `mid`. При слишком маленьком `mid` кусков получится больше `k` → невалидно. Диапазон по `mid` монотонен → бинарный поиск по ответу.
