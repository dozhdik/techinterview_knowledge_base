# Prefix Sum и range query паттерны

Ниже — три часто смешиваемых приёма. Их объединяет идея **накопления** информации по префиксу, но постановки и шаблоны кода различаются.

## Вариант A: одномерный префикс и запрос суммы на отрезке

**Когда:** много запросов «сумма с индекса `l` по `r`» на **неизменяемом** массиве (или после однократного препроцесса).

**Идея:** построить массив префиксных сумм `prefix[i+1] = prefix[i] + nums[i]`. Тогда `sum(l, r) = prefix[r+1] - prefix[l]` за `O(1)` на запрос после `O(n)` препроцесса.

## Вариант B: префиксная сумма + hash map (подотрезок с заданной суммой)

**Когда:** нужно найти **подмассив** с суммой `k` (или число таких подмассивов), часто при наличии отрицательных чисел, когда двумя указателями на отсортированность не упростить.

**Идея:** идти по массиву, хранить частоты уже встреченных префиксных сумм в hash map; переход от «сумма на отрезке» к «разность двух префиксов» остаётся той же математикой, но второй операнд ищется в map, а не через второй индекс префиксного массива.

**Уточнение:** это уже не классический «range query на статическом массиве», а **преобразование через префиксную сумму + частотная map / lookup** (сопоставление текущего префикса с уже накопленными в map или счёт пар префиксов).

Это **отдельный** интервью-шаблон от чистого range query: здесь ключевая структура — map, а не только массив `prefix`.

## Вариант C: двумерный префикс (матрица)

**Когда:** много запросов суммы (или другого аддитивного агрегата) на прямоугольнике в матрице без онлайн-обновлений.

**Идея:** префикс по строкам и столбцам; значение на прямоугольнике — комбинация четырёх значений на границах префикса (классическая формула inclusion на префиксах). Сложность препроцесса `O(rows * cols)`, запрос `O(1)`.

## Сводка: как не смешивать всё в одну кучу

- **A** — статический массив, чистые range sums.
- **B** — подотрезки с целевой суммой / счётчики через hash map по префиксу.
- **C** — 2D, те же идеи накопления, но две размерности.

## Когда применять (общие признаки)

- повторяющиеся вопросы про сумму, баланс `+1/-1`, количество единиц на отрезке и т.п.;
- формулировки вида `sum from l to r`, `subarray sum`, `number of subarrays...`;
- brute force по всем отрезкам даёт `O(n^2)` или хуже, а агрегат **аддитивен** по префиксу.

### Когда паттерн не подходит

- частые **точечные обновления** в массиве между запросами — нужны Fenwick / segment tree и т.п.;
- агрегат не сводится к разности префиксов;
- отрезков мало и препроцесс не окупается.

## Шаблон решения (вариант A)

```python
def build_prefix(nums: list[int]) -> list[int]:
    prefix = [0] * (len(nums) + 1)

    for i in range(len(nums)):
        prefix[i + 1] = prefix[i] + nums[i]

    return prefix


def range_sum(prefix: list[int], left: int, right: int) -> int:
    return prefix[right + 1] - prefix[left]
```

Для **варианта B** типичный каркас: один проход, переменная текущей префиксной суммы, `map[prefix_sum] -> count`, обновление ответа при фиксированной цели `k` (конкретная формула зависит от постановки).
