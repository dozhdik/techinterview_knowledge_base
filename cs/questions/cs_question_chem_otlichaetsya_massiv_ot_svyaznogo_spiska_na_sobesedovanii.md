# Чем отличается массив от связного списка на собеседовании

## Определение

Массив и связный список — это базовые линейные структуры данных, но они устроены по-разному и поэтому дают разный профиль производительности. Массив хранит элементы подряд в памяти, а связный список хранит элементы как цепочку узлов со ссылками друг на друга.

## Суть концепции

На собеседовании этот вопрос проверяет не способность воспроизвести таблицу сложностей, а понимание того, как физическая организация данных влияет на операции. Массив хорош там, где нужен **произвольный доступ по индексу** и **локальность данных в памяти** (cache locality). Связный список полезен там, где важна дешёвая локальная перестройка узлов, если позиция уже известна.

Главное отличие массива в том, что элементы лежат последовательно. Поэтому:
- доступ по индексу работает за `O(1)`;
- CPU cache работает эффективно;
- вставка или удаление в середине требует сдвига элементов и обычно стоит `O(n)`.

Связный список, наоборот, состоит из узлов, где каждый узел хранит значение и ссылку на следующий, а иногда и на предыдущий узел. Поэтому:
- доступа по индексу как у массива нет — до нужной позиции нужно дойти;
- поиск элемента или узла стоит `O(n)`;
- вставка или удаление после уже найденного узла может быть `O(1)`.

Именно здесь кандидаты часто ошибаются. Они говорят: “в linked list вставка `O(1)`, значит список лучше массива для вставок”. Это слишком грубое упрощение. Если позицию вставки ещё надо найти, общая стоимость часто остаётся `O(n)`. То есть сравнивать нужно не абстрактную операцию “вставка”, а полный сценарий.

В практической разработке массивы используются гораздо чаще, потому что:
- лучше работают с памятью;
- проще в реализации;
- эффективнее для большинства типовых сценариев;
- дают быстрый **произвольный доступ по индексу**.

Связные списки на собеседованиях встречаются чаще, чем в повседневной промышленной разработке, потому что они хорошо проверяют понимание указателей, ссылок, инвариантов и работы с краевыми случаями.

## Ключевые характеристики

- **Массив**:
    - элементы лежат подряд в памяти;
    - доступ по индексу `O(1)`;
    - вставка/удаление в середине `O(n)`;
    - хорошая **локальность данных в памяти** (cache locality).
- **Связный список**:
    - элементы хранятся в узлах со ссылками;
    - доступ по индексу `O(n)`;
    - вставка/удаление после найденного узла `O(1)`;
    - плохая **локальность данных в памяти** (cache locality).
- **Временная сложность**:
    - доступ по индексу: массив `O(1)`, список `O(n)`
    - поиск: массив `O(n)` без сортировки, список `O(n)`
    - вставка в середину: массив `O(n)`, список `O(1)` только если узел уже найден
- **Пространственная сложность**:
    - массив `O(n)`
    - связный список `O(n)`, но с дополнительными накладными расходами на ссылки

## Визуальное представление

```text
Массив:
index:   0    1    2    3
value: [10] [20] [30] [40]

Доступ к arr[2] -> O(1)


Связный список:
[10] -> [20] -> [30] -> [40] -> None

Чтобы получить 3-й элемент,
нужно пройти:
10 -> 20 -> 30
