# Экстрактивный поиск без LLM

По умолчанию `./scripts/run_rag.sh` запускает FastAPI в `.venv-rag` с `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`. Предварительно скачанная модель эмбеддингов и существующий `_data/vector_index.sqlite3` используются без Ollama и внешних сервисов. `RAG_ENABLED=true` с `RAG_BASE_URL` и `RAG_MODEL` явно включает прежний генеративный режим; интеграция и потоковый API сохранены. Обычный интерфейс ожидает готовый результат поиска и не имитирует генерацию.

Гибридное ранжирование остаётся в `kb/vector_store.py`: нормализация и технические алиасы, лексические признаки названия, тегов и текста плюс семантическое сходство. По ID открывается полная карточка; обычный запрос передаётся в гибридный поиск. `kb/extractive.py` выбирает верхнюю подходящую карточку и до трёх целых разделов по заголовкам и признакам вопроса. Кодовые блоки и предложения не обрезаются. Служебные разделы источников и ID-маркеры исключаются из ответа; исходная карточка открывается отдельной ссылкой. Алгоритм не перефразирует текст и не создаёт новые факты.

Модель эмбеддингов загружается при первом запросе и переиспользуется; разобранные карточки, подготовленные записи и строки SQLite кешируются с инвалидацией по метаданным файлов. При изменении содержимого старый индекс обновляется существующим механизмом с тем же backend и моделью. При отсутствии индекса или модели предусмотрен явно обозначенный резервный текстовый поиск. Нормальный путь не переключается на hash. Схема SQLite не менялась.

Проверка 24.11.2026 на копии реального индекса и локальной модели: первый запрос хеш-таблицы — 8,338 с, последующие содержательные запросы — 0,209–0,232 с; отсутствие совпадения — 0,184 с, точный ID — 0,014 с. Оба вопроса о BFS/DFS вернули `CS-QUESTION-003`, бинарный поиск — `CS-CONCEPT-018`, балансировщик — `ARCH-COMPONENT-001`, behavioral interview — `PROC-STAGE-005`. Квантовая запутанность не найдена. В первоначальном прогоне по горизонтальному масштабированию возвращалась частная карточка `ARCH-TRADEOFF-005`. После добавления общей карточки `ARCH-TRADEOFF-020` проверенные запросы о горизонтальном и вертикальном масштабировании возвращают её первой. Измерения — один прогон, не гарантия времени на другом оборудовании.

Ограничения: отбор пока показывает разделы одной наиболее релевантной карточки; многосоставные вопросы могут требовать нескольких источников. Ранжирование не гарантирует полноты ответа; некоторые разделы могут быть слишком общими. Локальный Markdown-рендерер отображает базовые таблицы, списки, выделение и блоки кода; формулы сохраняются как текст, сложные вложенные конструкции могут быть упрощены. Подробная карточка доступна по ссылке под ответом.
