# Локальный потоковый RAG

Чат использует существующий гибридный поиск и индекс `sentence-transformers`; переключение генеративной модели не меняет и не перестраивает индекс. По умолчанию скрипт запуска использует уже установленную `qwen3:4b-instruct` через локальный Ollama. Загрузка моделей и изменение системных настроек не требуются.

```bash
cd ~/techinterview_knowledge_base
ollama list
.venv-rag/bin/python main.py vector-status
RAG_ENABLED=true RAG_BASE_URL=http://127.0.0.1:11434/v1 RAG_MODEL=qwen3:4b-instruct RAG_NATIVE_API=true ./scripts/run_rag.sh
```

Откройте http://127.0.0.1:8000. При необходимости отдельно запустите установленный Ollama (`ollama serve`); если служба уже работает, второй экземпляр не нужен. Модель и адрес переопределяются без изменения файлов:

```bash
RAG_ENABLED=true RAG_BASE_URL=http://127.0.0.1:11434/v1 RAG_MODEL=qwen3:8b RAG_THINK=false RAG_NATIVE_API=true ./scripts/run_rag.sh
```

| Переменная | Начальное значение | Назначение |
| --- | --- | --- |
| `RAG_BASE_URL` | `http://127.0.0.1:11434/v1` в скрипте | Адрес Ollama/OpenAI-совместимого API |
| `RAG_MODEL` | `qwen3:4b-instruct` в скрипте | Установленная генеративная модель |
| `RAG_TEMPERATURE` | `0.3` | Температура |
| `RAG_NUM_CTX` | `4096` | Размер окна контекста Ollama |
| `RAG_NUM_PREDICT` | `512` | Максимум выходных токенов |
| `RAG_TIMEOUT_SECONDS` | `180` | Общий таймаут обращения к модели |
| `RAG_MAX_CHUNKS` | `6` | Максимум извлечённых фрагментов |
| `RAG_MAX_CONTEXT_CHARS` | `7000` | Дополнительный предел символов контекста |
| `RAG_KEEP_ALIVE` | `15m` | Время удержания модели Ollama |
| `RAG_THINK` | не задано | `false` или `true` для поддерживающих thinking моделей; для 4B Instruct специально задавать не требуется |
| `RAG_NATIVE_API` | `true` в скрипте | Для непотокового `/api/ask` использовать нативный Ollama API; `false` сохраняет OpenAI-совместимый вызов |
| `RAG_API_KEY` | пусто | Необязательный ключ, только в окружении |
| `RAG_EMBEDDING_BACKEND`, `RAG_EMBEDDING_MODEL`, `RAG_INDEX_PATH`, `RAG_MIN_SCORE` | прежние значения | Проверка и настройка существующего векторного индекса |

Веб-поток использует нативный Ollama `/api/chat` (для `RAG_BASE_URL`, оканчивающегося на `/v1`, суффикс удаляется). Для другого OpenAI-совместимого сервиса остаётся непотоковый `/api/ask` с `RAG_NATIVE_API=false`; потоковый режим требует нативный API Ollama. Не сохраняйте ключи в Git.

## Обработка и источники

`POST /api/ask` сохраняется для совместимости. `POST /api/ask/stream` отдаёт NDJSON: `stage` (search, context, generation, verify), `delta` (предварительный текст), `final`, `truncated` или `error`. Потоковое содержимое предварительное: при неверной ссылке оно удаляется из чата и не сохраняется как проверенный ответ. Кнопка «Остановить генерацию» прерывает браузерный запрос, закрывая соединение с Ollama. В случае `done_reason: length` ответ отмечается обрезанным и не сохраняется как полноценный.

Модель получает ID карточек и возвращает внутренние ссылки. Сервер проверяет каждый ID по фактически переданному контексту, отклоняет десятичные числа, отсутствующие в переданных фрагментах, удаляет маркеры из текста и возвращает уникальные ссылки в `sources`. Числовая проверка намеренно ограничена десятичными значениями и может давать ложные отказы; это не полная проверка фактов. Маркеры, разделённые между чанками, удерживаются на сервере. Список источников подтверждает только наличие карточки в контексте, но не доказывает истинность каждого утверждения. Системный промпт запрещает выполнение инструкций из документов, однако это не абсолютная защита от prompt injection и галлюцинаций.

Бюджет входа учитывает системную инструкцию, вопрос, фрагменты, выходной лимит и запас на служебное оформление. Вместо недоступного токенизатора генеративной GGUF-модели используется консервативная оценка по числу байтов UTF-8; она может заметно сокращать полезный контекст. Когда информации нет, генерация не запускается. При недоступном Ollama до начала генерации используется прежний поиск по карточкам. Точный ID по-прежнему открывает карточку напрямую.

Модель эмбеддингов кешируется в процессе; карточки и подготовленные записи индекса кешируются с инвалидацией по путям и метаданным файлов. Неизменившийся индекс не пересоздаётся; при изменении карточек сохраняется существующий режим его обновления с тем же backend и моделью. SQLite-схема не менялась.

## Диагностика

Логи Uvicorn показывают время загрузки карточек и модели эмбеддингов, вычисления эмбеддинга, поиска, подготовки контекста, первого видимого текста, генерации, проверки и полного запроса. После завершения Ollama также журналируются `load_duration`, `prompt_eval_count`, `prompt_eval_duration`, `eval_count`, `eval_duration`, `total_duration` в наносекундах, если API их предоставил. Диагностические метрики не выводятся в чат.

Тесты:

```bash
.venv-rag/bin/python -m pytest -q
.venv-rag/bin/python main.py vector-status
```

Сравнения и наблюдения конкретного запуска записаны в [отчёте измерений](rag_stream_measurements.md).

Если CDN библиотек Markdown недоступен, интерфейс использует локальный безопасный рендерер базовых заголовков, списков, выделения и блоков кода; сложный Markdown может отображаться упрощённо. Источники остаются отдельными ссылками под ответом.
