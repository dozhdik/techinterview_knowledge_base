# Векторный индекс базы знаний

Индекс используется retrieval-частью веб-чата, когда настроен генератор RAG. Сам индекс не вызывает языковую модель. Настройка чата описана в [rag_integration.md](rag_integration.md).

## Что создано

`kb/vector_store.py` читает карточки через действующий парсер, пропускает `draft` и материалы-заглушки, разбивает длинные карточки на фрагменты и сохраняет в SQLite их векторы и метаданные. В индекс попадают `cs/`, `arch/`, `process/` и, если каталог заполнен, `global/`. Разделы со списками связанных тем и источников исключаются из текста фрагментов: связи и источники сохраняются отдельными полями.

В каждой записи есть ID фрагмента (`ID_КАРТОЧКИ:номер`), ID и название карточки, область, категория, статус, путь к исходному Markdown-файлу, текст фрагмента, связанные ID, источники, контрольная сумма и вектор. Ссылка на карточку для RAG может быть построена как `/cards/{card_id}`. Поиск возвращает объект `VectorHit` с этими данными и оценкой сходства.

Текущий индекс находится в `_data/vector_index.sqlite3`. Это производный файл: он исключён из Git и восстанавливается командой `vector-build`. На момент создания в нём 225 карточек и 587 фрагментов.

## Режимы векторизации

| Режим | Назначение | Требования |
|---|---|---|
| `hash` | Локальный воспроизводимый индекс по словам и символьным фрагментам. Работает без новых библиотек и внешних сервисов. | Стандартная библиотека Python |
| `sentence-transformers` | Семантические эмбеддинги многоязычной модели. Для русских и английских запросов это предпочтительный режим перед подключением генерации. | Пакет `sentence-transformers` и доступная локально модель |

Команда `vector-status` показывает используемую модель. Режим `hash` хранит нормализованные векторы размерности 1024, отражающие совпадения слов и символьных фрагментов. При смене модели эмбеддингов команда построения заменяет несовместимые векторы.

Для текущего индекса используется `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` из окружения `.venv-rag`. При обычном запуске индекс перестраивать и модель загружать повторно не требуется. Если содержимое базы изменилось и индекс действительно нужно перестроить, явно используйте `.venv-rag/bin/python main.py vector-build --backend sentence-transformers`. Для другой модели можно указать идентификатор через `--model`; одна и та же модель должна применяться и для карточек, и для запросов.

## Команды

Из корня репозитория:

```bash
.venv-rag/bin/python main.py vector-build --backend sentence-transformers
.venv-rag/bin/python main.py vector-status
.venv-rag/bin/python main.py vector-search "Что такое хеш-таблица?" --limit 5
.venv-rag/bin/python main.py vector-search "репликация базы данных" --domain arch --min-score 0.15
```

`vector-build` обновляет только изменившиеся фрагменты и удаляет записи удалённых карточек. По умолчанию фрагмент ограничен 1400 символами; размер задаётся через `--max-chars`. `vector-status` показывает количество карточек и фрагментов, модель, размерность и актуальность относительно исходных Markdown-файлов. `vector-search` отказывается использовать устаревший индекс и предлагает перестроить его.

## Использование в RAG

CLI и веб-чат вызывают `search_index(root, question, limit=5, domain=None, min_score=0.0)` из `kb/vector_store.py`. Поиск сравнивает термины вопроса с названиями, тегами из YAML и текстом фрагментов. Алиасы из `_TECHNICAL_ALIASES` в `kb/search.py` приводят к одному термину русские и английские названия, аббревиатуры и поддерживаемые формы слов. Для нового синонима достаточно дополнить этот словарь. Изменения ранжирования применяются к существующим векторам и схеме SQLite.

Точное совпадение нормализованного названия и полное совпадение темы в названии имеют наивысший приоритет. Внутри группы порядок определяют лексическая оценка (75%) и косинусное сходство (25%). Редкие термины, заголовки и теги имеют больший вес, чем отдельные упоминания в тексте. Совпадение только в тексте допускается при достаточном покрытии вопроса, редком термине в найденном фрагменте и минимальном косинусном сходстве 0.25 для `hash` или 0.35 для `sentence-transformers`. Запросы определения требуют совпадения с названием или тегами. Сначала выдаётся по одному лучшему фрагменту каждой карточки, затем остальные фрагменты.

`VectorHit.score` и число в выводе CLI по-прежнему показывают косинусное сходство. `--min-score` и `RAG_MIN_SCORE` задают дополнительный порог для всех результатов. У запроса без лексических совпадений выдача может быть пустой даже при высоком косинусном сходстве. Это ограничивает случайные совпадения, но снижает полноту для переформулировок, которых нет в словаре синонимов.

Векторы читаются из SQLite. Python считает сходство для фрагментов, прошедших лексический отбор. При заметном росте корпуса стоимость чтения и сравнения стоит измерить отдельно. [Документация Sentence Transformers](https://sbert.net/examples/sentence_transformer/applications/semantic-search/README.html).

При включённом RAG отсутствующий индекс не создаётся автоматически; при несовпадении настроенного backend или модели используется резервный поиск. Индекс не следует перестраивать без необходимости. Если перестроение необходимо, явно укажите `--backend sentence-transformers` и перед этим проверьте `vector-status`.

## Повторные запросы и потоковый чат

Модель эмбеддингов кешируется по backend и имени внутри процесса. Подготовленные записи карточек кешируются с инвалидацией при добавлении, удалении или изменении Markdown-файла; проверка актуальности и поиск используют один снимок индекса. Веб-поиск остаётся гибридным, а смена LLM не меняет векторы. Потоковый протокол, параметры и ограничения описаны в [rag_integration.md](rag_integration.md).
