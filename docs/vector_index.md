# Векторный индекс базы знаний

Индекс используется retrieval-частью веб-чата, когда настроен генератор RAG. Сам индекс не вызывает языковую модель. Настройка чата описана в [rag_integration.md](rag_integration.md).

## Что создано

`kb/vector_store.py` читает карточки через действующий парсер, пропускает `draft` и материалы-заглушки, разбивает длинные карточки на фрагменты и сохраняет в SQLite их векторы и метаданные. В индекс попадают `cs/`, `arch/`, `process/` и, если каталог заполнен, `global/`. Разделы со списками связанных тем и источников исключаются из текста фрагментов: связи и источники сохраняются отдельными полями.

В каждой записи есть ID фрагмента (`ID_КАРТОЧКИ:номер`), ID и название карточки, область, категория, статус, путь к исходному Markdown-файлу, текст фрагмента, связанные ID, источники, контрольная сумма и вектор. Ссылка на карточку для RAG может быть построена как `/cards/{card_id}`. Поиск возвращает объект `VectorHit` с этими данными и оценкой сходства.

Текущий индекс находится в `_data/vector_index.sqlite3`. Это производный файл: он исключён из Git и восстанавливается командой `vector-build`. На момент создания в нём 225 карточек и 587 фрагментов.

## Режимы векторизации

| Режим | Назначение | Требования |
|---|---|---|
| `hash` | Локальный воспроизводимый индекс по словам и символьным фрагментам. Работает без новых библиотек и внешних сервисов. | Стандартная библиотека Python |
| `sentence-transformers` | Семантические эмбеддинги многоязычной модели. Для русских и английских запросов это предпочтительный режим перед подключением генерации. | Пакет `sentence-transformers` и доступная локально модель |

Индекс, который построен сейчас, использует `hash`. Он хранит нормализованные векторы размерности 1024 и ищет по косинусному сходству, но его близость в основном лексическая: перефразирование без общих слов может не найти нужную тему. Этот режим полезен для разработки и проверки контракта retrieval. Для семантического поиска индекс нужно перестроить с моделью; смешивать векторы разных режимов нельзя. При перестроении несовместимые векторы автоматически заменяются.

Для режима Sentence Transformers по умолчанию выбрана `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`. Он подключается по желанию:

```bash
venv/bin/python -m pip install sentence-transformers
venv/bin/python main.py vector-build --backend sentence-transformers
```

Первое использование модели может потребовать её загрузки. После установки можно указать другой идентификатор через `--model`; одна и та же модель должна применяться и для карточек, и для запросов. Пакет и веса модели в базовое окружение проекта не добавлялись.

## Команды

Из корня репозитория:

```bash
venv/bin/python main.py vector-build
venv/bin/python main.py vector-status
venv/bin/python main.py vector-search "Что такое хеш-таблица?" --limit 5
venv/bin/python main.py vector-search "репликация базы данных" --domain arch --min-score 0.15
```

`vector-build` обновляет только изменившиеся фрагменты и удаляет записи удалённых карточек. По умолчанию фрагмент ограничен 1400 символами; размер задаётся через `--max-chars`. `vector-status` показывает количество карточек и фрагментов, модель, размерность и актуальность относительно исходных Markdown-файлов. `vector-search` отказывается использовать устаревший индекс и предлагает перестроить его.

## Использование в RAG

Retrieval вызывается через `search_index(root, question, limit=5, domain=None, min_score=0.0)` из `kb.vector_store`. Веб-чат использует `kb.rag` поверх этого поиска: обновляет индекс при изменениях карточек, ограничивает передаваемый контекст и проверяет ID в ответе модели. Возвращаемые `VectorHit` содержат текст фрагмента и данные для ссылки на исходную карточку. Порог `min_score`, число фрагментов и качество выдачи следует проверить на наборе реальных вопросов; сам по себе высокий score не подтверждает истинность ответа.

В текущей реализации SQLite выполняет точный перебор векторов. Для нескольких сотен фрагментов этого достаточно; при заметном росте БЗ понадобится специализированный индекс ближайших соседей. Документация по семантическому поиску: [Sentence Transformers](https://sbert.net/examples/sentence_transformer/applications/semantic-search/README.html).
