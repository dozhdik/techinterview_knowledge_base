# Изменения веб-MVP TechInterview Knowledge Base

Документ описывает первоначальное подключение веб-MVP к Markdown-базе знаний. Дополнительная интеграция RAG описана в [rag_integration.md](rag_integration.md).

## Что изменилось

Изначально веб-интерфейс принимал вопрос, но сервер выбирал один из трёх заранее написанных ответов по ключевым словам. При неизвестной теме мог возвращаться случайный ответ. Источники были указаны в коде и не открывали карточки.

Теперь чат читает Markdown-карточки базы знаний, ищет подходящий материал и выводит текст найденной карточки. Под ответом отображаются ссылки на источники. Для отсутствующих тем, неизвестных ID и незаполненных карточек предусмотрены отдельные сообщения.

В режиме без настроенного генератора веб-MVP использует локальный лексический поиск и возвращает готовый текст карточки. При настройке генератора доступен RAG по векторному индексу.

## Состав решения

| Компонент | Назначение |
|---|---|
| `web/server.py` | FastAPI, загрузка карточек, обработка запросов и выдача страниц |
| `kb/parser.py` | Чтение Markdown и YAML-метаданных, формирование объектов `KnowledgeUnit` |
| `kb/search.py` | Поиск по вопросу и ранжирование карточек |
| `kb/content.py` | Проверка, заполнен ли материал карточки |
| `web/static/js/chat.js` | Отправка вопроса, показ ответа, источников и истории чата |
| `web/static/js/card.js`, `web/static/card.html` | Просмотр отдельной карточки и сообщения о её недоступности |
| `web/static/js/utils.js` | Безопасное отображение Markdown |

Карточки хранятся в каталогах `cs/`, `arch/`, `process/` и `global/`. При каждом запросе сервер заново читает файлы этих каталогов, поэтому изменение, добавление или удаление карточки отражается в следующем ответе без перезапуска сервера. Служебные файлы не участвуют в поиске.

## Как обрабатывается вопрос

1. Браузер отправляет JSON-запрос `POST /api/ask` с полем `question`. Пустой вопрос получает сообщение об ошибке; длина вопроса ограничена 1000 символами.
2. Если вопрос содержит ID вида `CS-CONCEPT-009`, сервер ищет именно эти карточки. Неизвестные ID перечисляются в ответе. Если вместе с ними запрошены существующие заполненные карточки, их материалы также показываются.
3. Для обычного вопроса поиск выделяет слова, приводит их к нижнему регистру, заменяет `ё` на `е`, удаляет служебные слова и применяет упрощённую нормализацию русских окончаний. Несколько распространённых вариантов терминов, например `hash` и `хэш`, сопоставляются с одним написанием.
4. Термины сравниваются с названием, именем файла, тегами и содержимым карточек. Совпадение в названии или имени файла получает вес 8, в тегах — 4, в тексте — 1. Редкие для базы слова имеют больший вес. Карточка должна содержать не менее 75% значимых терминов вопроса; хотя бы один термин должен совпасть с названием, именем файла или тегом.
5. Для вопроса об определении дополнительно требуется совпадение термина с названием или именем файла в нужном порядке либо с набором тегов. Это уменьшает вероятность ответа по случайному упоминанию темы внутри другого материала.
6. Результаты сортируются по релевантности. Чат выводит полный текст первой подходящей карточки и до трёх ссылок на найденные заполненные карточки.

Например, вопрос «Что такое хеш-таблица?» открывает материал по хеш-таблице. Вопрос «Что такое дерево Меркла?» сообщает, что подходящего определения пока нет, хотя слово «дерево» встречается в других карточках.

## Отсутствующие и незаполненные материалы

| Ситуация | Поведение чата |
|---|---|
| ID отсутствует | Сообщает, какой именно ID не найден; источники отсутствуют |
| Тема или определение не найдены | Предлагает уточнить название темы или указать ID |
| Карточка существует, но содержит только шаблон | Сообщает, что материал ещё не заполнен; шаблон как ответ не показывается |
| Запрошены несколько ID | Показывает доступный материал и отдельно перечисляет отсутствующие или незаполненные карточки |

При открытии ссылки на неизвестную карточку страница возвращает HTTP 404 и показывает сообщение. Для карточки с незаполненным материалом используется HTTP 409. На странице доступна ссылка для возврата в чат.

## API и интерфейс

| Адрес | Результат |
|---|---|
| `POST /api/ask` | Ответ в JSON с полями `status`, `answer`, `sources`, `confidence`, `is_rag_enabled` |
| `GET /api/units/{id}` | Данные заполненной карточки; HTTP 404 для неизвестного ID, HTTP 409 для незаполненной карточки |
| `GET /cards/{id}` | HTML-страница карточки с теми же состояниями доступности |

У `POST /api/ask` HTTP-статус обычно равен 200, а поле `status` уточняет результат: `success`, `not_found`, `not_ready` или `error` для пустого вопроса. Некорректная структура запроса возвращает HTTP 422. Значение `confidence` равно `null`; `is_rag_enabled` равно `true` для ответа, сгенерированного по найденным фрагментам.

Источники под ответом стали ссылками на реальные карточки. Markdown перед показом проходит очистку HTML; это относится также к сообщениям, восстановленным из истории браузера. История чата и выбранная тема оформления сохраняются в `localStorage`. Для Markdown и подсветки кода интерфейс загружает библиотеки с CDN.

## Запуск и проверка

Из корня репозитория:

```bash
venv/bin/python -m uvicorn web.server:app --reload --port 8000
```

Открыть интерфейс: <http://localhost:8000>. Документация API: <http://localhost:8000/docs>.

Проверка проекта:

```bash
PYTHONDONTWRITEBYTECODE=1 venv/bin/python -m pytest tests/ -q -p no:cacheprovider
```

Тесты проверяют поиск по нескольким словам, ранжирование, реальные ответы из карточек, изменения файлов без перезапуска, неизвестные ID, отсутствующие определения, незаполненные шаблоны и HTTP-ответы страниц источников. На момент подготовки документа все 218 тестов проходят.

## Текущие ограничения

Поиск работает по словам и небольшому набору правил нормализации, поэтому не понимает смысл вопроса так, как языковая модель. Чат возвращает готовый текст карточки целиком и не проверяет фактическую правильность материала. Постоянного поискового индекса нет: файлы и поисковые представления перечитываются при каждом запросе. Точность обработки незаполненных материалов зависит от того, распознаёт ли проверка шаблон в содержимом карточки.
