# Фреймворк решения задач на coding-интервью

## Что это
Универсальный 5-шаговый подход к решению алгоритмических задач на собеседовании. Помогает структурировать мышление, не пропускать важные этапы и демонстрировать интервьюеру системный подход.

## Зачем использовать
- Не начинать писать код сразу без понимания задачи
- Показать, что ты умеешь декомпозировать проблемы
- Уменьшить вероятность ошибок и упущенных edge cases
- Демонстрировать коммуникацию на всём протяжении решения

## 5 шагов фреймворка

### 1. UNDERSTAND (Понять задачу) — 3-5 мин
**Что делать:**
- Переформулировать задачу своими словами
- Задать уточняющие вопросы:
  • Формат входных/выходных данных?
  • Ограничения по размеру/значениям?
  • Массив отсортирован? Есть ли дубликаты?
  • Что возвращать, если решения нет?
- Привести 2-3 примера input → output

**Фразы-помощники:**
- «Правильно ли я понял, что...»
- «Можно уточнить, может ли вход быть пустым?»
- «Давайте я приведу пример, чтобы убедиться...»

### 2. EXAMPLES (Примеры и edge cases) — 2-3 мин
**Что делать:**
- Записать примеры из условия
- Добавить edge cases:
  • Пустой input (массив, строка)
  • Один элемент
  • Отрицательные числа / нули
  • Очень большие значения
  • Дубликаты, уже отсортированные данные

**Зачем:** Показывает, что ты думаешь о надёжности кода заранее.

### 3. BRUTE FORCE (Наивное решение) — 3-5 мин
**Что делать:**
- Описать самый простой подход
- Написать псевдокод или кратко объяснить логику
- Оценить сложность: Time O(...), Space O(...)
- Объяснить, почему это не оптимально

**Зачем:** Демонстрирует, что ты можешь решить задачу в принципе, и создаёт базу для оптимизации.

### 4. OPTIMIZE (Оптимизация) — 5-7 мин
**Что делать:**
- Найти bottleneck наивного решения
- Вспомнить подходящий паттерн или структуру данных:
  • Two Pointers для отсортированных массивов
  • Hash Map для быстрого поиска
  • Sliding Window для подмассивов/подстрок
  • BFS/DFS для графов/деревьев
- Описать идею оптимизированного подхода
- Пересчитать сложность

**Фразы-помощники:**
- «Здесь можно ускорить поиск, если использовать хеш-таблицу...»
- «Поскольку массив отсортирован, подойдёт бинарный поиск...»

### 5. CODE & TEST (Код и тесты) — 15-20 мин
**Что делать:**
- Написать чистый, читаемый код
- Комментировать неочевидные моменты
- Протестировать на примерах из шага 2
- Исправить баги, если обнаружились
- Кратко озвучить итоговую сложность

**Чек-лист кода:**
- [ ] Понятные имена переменных
- [ ] Нет дублирования логики
- [ ] Обработаны edge cases
- [ ] Код работает на примерах

## Типичные ошибки

❌ **Сразу писать код** — пропускаешь шаги 1-4
✅ Остановись, задай вопросы, продумай подход

❌ **Молча решать** — интервьюер не видит ход мыслей
✅ Комментируй каждый шаг: «Сейчас я проверю... потому что...»

❌ **Забыть edge cases** — код падает на пустом входе
✅ Всегда тестируй минимум 3 случая: обычный, граничный, пустой

❌ **Не оценить сложность** — не можешь обосновать выбор
✅ В конце кратко: «Time O(n), Space O(1), потому что...»

## Адаптация под уровни

**Junior:**
- Достаточно пройти все 5 шагов, даже если оптимизация простая
- Главное — чистый код и понимание базовых структур

**Middle:**
- Ожидается уверенное применение паттернов (Two Pointers, Sliding Window)
- Умение предложить 2 подхода и обосновать выбор

**Senior:**
- Глубокий анализ trade-offs, обсуждение альтернатив
- Способность масштабировать решение («А если данных 1 млрд?»)
